## Requirements
### Requirement: 依赖系统身份与权限归并

系统 SHALL 以已确认的 provider system 身份保存依赖权限；DSF 通道名仅用于展示。同一 provider 同时作为上游和下游时 MUST 显示一张卡片、共用一份权限。无法确认 provider 或接口身份的引用 MUST 保留引用证据，解析登记前不得显示可执行开关或授权调用。不得只凭删除前缀或相似名称合并系统。

#### Scenario: 同一系统上下游合并

- **WHEN** 扫描证据确认上游 `ifightchainsaas.java.booking.core` 和下游通道 `dsf.ifightchainsaas.booking.core` 属于同一已注册提供方
- **THEN** 页面只显示一张系统卡片，标记上游和下游两个角色
- **AND** 通道名作为别名展示，不创建第二份授权

#### Scenario: 未解析外部引用

- **WHEN** 引用无法明确映射到已注册提供方或其接口
- **THEN** 页面显示原始引用和待解析提示
- **AND** 不显示该引用的授权开关，不把它计为可授权接口

### Requirement: 构造权限分层

接口 SHALL 支持逐项开关和当前系统全部接口一键开启，批量范围 MUST 包括已加载目录中未展示的接口及写接口，并与数据库权限独立。新授权 MUST 保存精确接口集合，不隐式授权以后新增接口；已有只读授权须保留。新发现接口默认未授权。源码扫描、直接数据库读取、创建、修改、删除权限 MUST 分开保存。

#### Scenario: 全部接口一键开启

- **WHEN** 用户点击一个系统的全部开启
- **THEN** 当前已发现且身份已确认的全部接口都变为开启，包括写接口和当前筛选隐藏的接口
- **AND** 数据库与源码开关保持原值，后来新增接口不会自动开启

#### Scenario: 数据库权限不扩大接口权限

- **WHEN** 用户只开启数据库创建权限
- **THEN** 系统不因此获得任何接口调用、数据库修改或删除权限
- **AND** 数据库写入经现有数据函数和执行器，调用前按实际SQL动作、明确允许表和有界行数校验
- **AND** 仅允许qa和uat环境；创建使用单行参数化INSERT，修改删除须带条件和LIMIT 1至100

### Requirement: 权限目录与懒加载

系统页 SHALL 默认折叠系统，展开时只加载该系统的完整接口目录。默认展示已授权与引用接口的并集，按 Facade/类自动展开分组；用户可展示全部接口。页面 MUST 只用权限开关，不附加选择复选框，并以统一保存或取消提交草稿。权限按当前员工、当前系统和qa/uat环境隔离。

#### Scenario: 展开系统按需加载

- **WHEN** 用户展开一个依赖系统
- **THEN** 页面只请求并派生该系统接口，不提前加载所有提供方的完整接口
- **AND** 加载失败保留授权并提供重试

#### Scenario: 草稿与环境隔离

- **WHEN** 用户修改权限后切换接口筛选或折叠系统
- **THEN** 修改仍保留，取消可恢复最近成功读取或保存的值
- **AND** 未保存时切换环境或刷新须先保存或取消；旧环境请求响应不得覆盖新环境

#### Scenario: 保存部分失败

- **WHEN** 多个系统依次保存且某个系统失败
- **THEN** 已成功项保持保存状态，失败及未提交项保留草稿，并明确提示失败

### Requirement: Case 编译与执行权限检查

Case 编译 SHALL 使用任务员工、环境和当前系统保存的依赖权限；未授权依赖操作 MUST 不进入可执行能力集合。实际调用前 MUST 重读当前权限，撤销后不可通过旧Case继续调用。目标系统本地入口不受依赖权限限制；存放于调用方目录的外部DSF接口仍须检查真实提供方授权。

#### Scenario: 未授权写接口被过滤

- **WHEN** 依赖系统写接口未被授权
- **THEN** Case 编译不得把该操作作为可执行依赖
- **AND** 引用该操作的执行被明确阻塞，而不是静默改用其他接口

#### Scenario: 授权撤销与外部接口

- **WHEN** 依赖授权在Case生成后被撤销，或者外部DSF定义存放在当前系统目录
- **THEN** 实际调用前仍按已确认提供方及请求环境检查当前员工授权
- **AND** 无授权时不派发业务请求

#### Scenario: 已有任务的源码权限撤销

- **WHEN** 用户关闭某依赖系统的源码扫描权限
- **THEN** Case及数据任务的每次源码工具读取都按任务员工及创建环境重新检查，已有来源范围不能绕过
- **AND** 数据任务明确保存创建环境，旧任务默认QA；共享函数的实际试跑按当次员工与执行环境检查

### Requirement: 依赖接口目录仅授权实际提供方的对外接口

每个已注册依赖系统卡片 SHALL 仅将该系统自身的 Facade 对外接口作为可授权接口。系统调用其他提供方的外部 DSF、MQ 操作及数据库操作 MUST NOT 混入该接口列表；数据库能力仍使用独立数据库权限。默认已选与引用视图、全部接口数量、一键全开和保存校验 MUST 共用此范围，不得以目录所在系统代替真实提供方。

#### Scenario: 提供方目录含有外部调用

- **WHEN** 补单系统目录同时存在自身的 CallbackFacade 接口及其调用退票、出票系统的外部 DSF 接口
- **THEN** 补单系统卡片仅将自身的 Facade 对外接口列为可授权接口
- **AND** 外部调用、MQ 和数据库操作不计入全部接口与全部开启范围，方法同名也不得混淆归属

#### Scenario: 历史误存授权不能扩大实际提供方权限

- **WHEN** 旧补单系统权限保存了下游外部接口或 MQ 操作 ID
- **THEN** 这些 ID 不在补单系统接口列表显示为已选，保存时不得将它们作为该系统接口接受
- **AND** 旧外部 ID 不能代替真实提供方 Facade 的精确授权，旧 MQ ID 不能通过接口权限被执行
- **AND** 补单系统原有合法 Facade 授权及独立数据库权限仍然保留

#### Scenario: 当前系统引用依赖提供方

- **WHEN** 当前系统调用补单系统的外部 DSF 定义已明确映射到补单系统对外 Facade
- **THEN** 补单系统卡片展示并标记该 Facade 为引用，编译及执行按其精确授权检查
- **AND** 上下游角色合并规则和未解析引用的只读提示保持有效
