# Java语义知识与三栏工作台设计

## 可替换分析器

Python只依赖`JavaSemanticAnalyzer`端口和版本化JSON契约。默认本地Sidecar使用JavaParser与Symbol Solver解析源码根、重载、继承、接口分派、注解和枚举构造绑定；解析器专有类型不进入领域模型。未解析边保存原因和低置信度，现有确定性扫描只补充明确缺口，不建立第二套重复调用图。

公共逻辑只收录跨两个以上知识入口复用的业务符号，或具有状态机、责任链、事件链明确结构证据的符号。状态机、责任链等使用相同`logic:<symbol>`节点，以分类元数据投影到`公共逻辑`目录。

## 状态标签

枚举常量保留稳定code。分析器输出类型级和常量级Javadoc摘要，并从声明字段、构造参数赋值和getter绑定中选择`name`、`desc`、`description`描述。逐值含义优先采用有效常量Javadoc，其次使用唯一构造绑定，最后回退稳定code；类级业务注释可用时作为名称，否则暂用Java枚举名。注释或代码标识形成`CODE_DEFAULT`，表示“代码默认、可人工修订”，不会冒充`USER_CONFIRMED`。

## 问题周期

访谈规划器先消费代码事实、四项核心背景和业务术语，再把仍无法判断且影响业务行为、责任边界、异常结果或测试判断的开放问题固定为一个`KnowledgeQuestionCycle`。周期绑定系统、不可变`scan_id`、问题集合摘要、逐题暂存答案和本地重算任务；前置关系只用于解释与排序，不隐藏已发现问题。历史`question:business-name:*`、枚举维护、技术辅助方法、类名翻译和调用链已能证明的用途不得进入新周期。问题保留分类、优先级、提问原因、影响目标和源码证据，相同疑点跨目标合并并复用稳定历史答案。

单题保存只更新Git忽略的本地周期文件，不写`USER_CONFIRMED`，也不触发分析。所有问题均有答案后，用户通过“完成本轮并重新分析”统一确认；“暂不确定”算已填写，但转为持续显示的受影响知识与测试阻塞项。优先级、分类和当前对象筛选只改变可见卡片，不改变整轮完整性。

右栏在完整周期之上提供“未填写 / 已填写 / 全部问题”三个Tab，默认未填写。“已填写”只计算当前周期非空暂存答案，包含“暂不确定”；保存后问题立即迁移到已填写。Tab与范围、优先级、分类筛选共同决定可见卡片，但问题徽标、缺答数量和完成门禁始终按整个周期计算。系统或周期变化时重置为未填写。

完成动作校验系统、周期ID、问题摘要、最新Manifest指针和当前源码基线。问题或源码变更返回稳定stale冲突，新周期仅继承稳定问题ID仍匹配的暂存答案。完成后复用周期Manifest执行本地知识重算，不重复源码全扫描，不调用Agent、QA或业务接口；任务失败保留原周期和答案，进入可幂等重试的`BLOCKED`状态。历史周期按ID保留，使重复完成在新周期生成后仍返回首次任务。

## 代码事实吸收

候选保持原稳定ID、`kind`和存储路径，并用`knowledge_form`区分普通术语、业务枚举和外部应用。业务枚举分别保存业务名称及来源、结构化code/含义/来源/置信度/证据；`CODE_VERIFIED`表示唯一构造绑定，`CODE_DEFAULT`表示注释或代码标识提供的可修订默认值。枚举不进入集中问答周期：注释缺失、同名类型或常量回退均保留明确代码来源并直接展示，避免把逐项维护成本转移给业务用户。重扫刷新代码默认值但保护`USER_CONFIRMED`人工名称和值；同名类型冲突使展示code变化时按值级全限定源码符号迁移人工含义，无法唯一匹配则保留原值并转为复核。候选合并后重新执行严格模型校验，纯代码状态不得混入人工值、已知未知或缺少值级证据的来源。旧YAML按兼容默认值读取，并在下一次语义发现时迁移为业务枚举而不改变ID、人工回答或历史状态。旧枚举问题周期在下一次读取时因问题摘要变化转为`STALE`，无需重新填写。

语义Sidecar同时输出类型的直接字段引用与集合标记。页面只把直接声明关系作为核心对象问题前提，不从字段推断业务所有权、生命周期归属或未证明基数。

## 三栏工作台

知识库顶部以既有视觉体系展示四步流程条：完善背景、生成知识、确认疑点、使用与修订。流程条根据持久化事实投影完成、当前、待处理、部分失败和知识过期，不建立第二套状态机；同时展示当前Agent、已处理目标数、活动或最近任务以及唯一下一步操作。桌面横向展示，390×844使用四列短标签并在下方解释当前步骤。

左栏组织业务背景、接口文档、公共逻辑、业务术语、业务枚举和外部应用，并固定提供“全部待确认问题（N）”。普通目标被选择后，右栏立即切换为当前对象范围；全部问题入口在中栏展示周期概览并让右栏按每页20项渐进渲染。业务枚举为单层列表，以类注释或Java枚举名形成的默认名称为主标题、Java符号为次级标识，并逐字段显示`CODE_DEFAULT / CODE_VERIFIED / INFERRED / USER_CONFIRMED`来源。中栏展示已经发布的确定性事实、Agent代码解释和人工知识，未确认修订草稿只在右栏出现。从背景、接口或公共逻辑进入术语、枚举或应用详情时保存轻量返回栈，返回恢复原知识、聊天、问题对象筛选和移动抽屉状态；系统或扫描周期变化时清空。

业务背景详情允许显式保存系统定位、核心对象、成功主流程、上下游责任边界和原有其他背景答案，也允许新增、修改或删除业务术语。四项核心背景非空且不是“暂不确定”时，用户首次点击“背景与术语已完善”写入永久完成时间；后续编辑不重新打开步骤1，也不自动调用Agent。系统级背景变化把全部知识标记为过期；术语变化优先使用`affected_target_ids`精确标记，无法定位时保守影响全部目标。旧知识仍可浏览，用户需重新显式选择Agent和范围后更新。

页面只允许对当前选中的一个`NOT_GENERATED / STALE / CODE_ONLY / FAILED`目标生成知识，暂时下掉“生成全部”；旧批量路由只兼容一个目标，多个目标在创建任务前拒绝。方法体定位先屏蔽注释和字面量，再区分类型与方法声明、跳过更早调用点并配平参数和正文；方法或构造器声明不计作调用或副作用，源码引用复用真实声明偏移。合法入口仅能证明方法存在时发布明确边界的最小`CODE_VERIFIED`事实，不因内容较浅提问。目录清楚区分未生成、生成中、已生成、仅代码事实、待确认、已确认、已过期和生成失败。

## Agent选择与逐目标生成

Git忽略的全局本地设置保存`knowledge_agent = "" | "codex" | "claude"`，初始为空且应用于所有系统。知识页始终显示当前选择并提供显式切换；按钮必须带Codex或Claude Code名称。提交当前对象前，页面展示Agent、目标范围、目标数量1、注册源码根内只读边界和可能产生API费用，只有用户确认后才发送带必填`agent`的请求。任务运行期间修改全局选择只影响新任务。

后端只执行请求指定且与全局选择一致的Agent，不得自动选择、跨Agent切换或兜底。Agent不可用时阻止提交。单目标任务依次执行确定性源码追踪、指定Agent只读分析、严格输出校验、按来源发布和结果检查点：确定性事实为`CODE_VERIFIED`，Agent代码解释为`INFERRED`，用户后续确认才是`USER_CONFIRMED`。指定Agent失败时保存确定性事实并标记`CODE_ONLY / Agent失败`；确定性追踪也失败才标记`FAILED`。

Codex使用`exec --json --output-schema`并保存thread ID，Claude Code使用`stream-json --include-partial-messages`并保存session ID；两者标准输入均关闭，不设置固定分析超时，不使用临时会话。工作进程把公开推理摘要、Agent消息、用量、校验、发布、等待回答和终态保存为带单调序号的0600 JSONL，不保存到页面的内容包括提示词、认证信息、供应商原始事件和隐藏思维链；首次观察到会话ID时立即更新恢复状态。SSE按`Last-Event-ID`首次定位后保存当前连接的字节位置，只解析新增完整事件行；静默期用状态文件心跳、累计耗时和最后活动时间证明进程仍存活，旧轮询保留为降级路径。

Agent返回`needs_input`时立即发布确定性代码事实，暂缓未完成推断并把结构化文本、单选或多选问题放入当前对象右栏；任务进入`WAITING_FOR_INPUT`并释放全局门禁，同时保存问题来源运行、周期ID和固定问题摘要。只有该周期完成后，用户再次确认原Agent和费用，系统才以原thread/session ID创建下一尝试；续跑中断且当前尝试尚未记录会话ID时回退到问题来源会话，绝不采用后来修改的全局Agent。页面或SSE重连只读取原事件；服务重启以持久handoff标记、所有权心跳和孤儿付费任务门禁协调接管，工作进程仍存活则继续读取，已有最终输出则继续校验发布，进程消失才标记中断并要求用户再次确认，均不得静默创建第二次付费调用。没有接管契约的知识聊天在服务关闭时继续等待，不会错误分离共享Runner。

目标详情页面使用轻量响应，不重复执行完整`list_questions()`和`get_context()`；关联问题由前端从已加载周期筛选。问题周期普通读取返回持久化快照，只在扫描、生成、回答或修订后显式重算。初始三栏、切换目标、保存、确认、发布、刷新与重试都提供范围对应的骨架或忙碌状态、`aria-busy`和状态播报并防重复点击；失败保留旧内容，同时显示常驻错误摘要、Toast和重试入口。

## 修订式知识聊天

中栏底部保存绑定当前背景、候选、接口或公共逻辑的聊天历史。只有用户点击“发送并分析”或重试时才运行现有本地只读Agent；请求不包含QA、Fixture或敏感设置，Agent只收到固定Manifest、已确认知识、当前作用域证据和用户消息。Agent输出必须通过严格结构、系统、扫描、作用域、源码证据和精确前后值校验，且不能产生`CODE_VERIFIED`或直接修改知识。背景和候选口径可声明`USER_MESSAGE`证据，节点源码修订必须声明`SOURCE_REFERENCE`且至少选择一条当前作用域规范引用；Agent提供的repository、commit和内容摘要一律替换为服务端固定引用。

合法的背景更新、候选新增、候选修订或节点修订各自转换为`source=conversation`的右栏固定选择题：“确认发布 / 暂不确定”。确认卡由服务端确定性展示写入目标、真实before/proposed逐节点差异和证据基础，不采用Agent自述标题或详情。同一信封、现有开放问题和其他未决会话不得争写同一背景问题、候选或节点。每项提案的发布摘要只绑定其真实背景项、候选或目标节点依赖，使不同写目标的未决会话可独立收敛；同一Agent信封中的后续提案只按各自依赖安全重基。

完成周期时不调用Agent，并优先应用会话问题；确认发布才在系统锁内应用人工知识并重建必要索引，暂不确定不发布。多节点发布记录`not_started / partial / published`并只续写仍精确等于before的节点；部分恢复只归一化本提案已经精确写入的正文和原状态，所选目标内其他变化仍返回稳定stale。节点正文全部落盘但索引重建失败时，重试必须再次幂等重建索引，成功后才能记录发布终态。知识、Manifest或前值变化返回稳定stale冲突。Agent不可用、非法输出或信息不足时保留消息为`BLOCKED`且允许显式重试，不生成猜测问题。新消息只取代同一作用域未确认提案，其他问题和稳定暂存答案继续继承。

## 本地存储

Git知识文件继续保存人工含义、答案和已发布正文；Sidecar结果、问题投影和调用边摘要保存为可重建派生资产。未确认的周期与暂存答案保存在`.opentest/knowledge-question-cycles/<system>`的0700目录和0600文件中，会话轮次与提案保存在`.opentest/knowledge-conversations/<system>`的0700目录和0600原子文件中，并随系统归档。旧Manifest、缺少类型关系的语义结果、问题和知识节点使用兼容默认值读取，人工内容不因重扫被覆盖。
