# Java语义知识与三栏工作台设计

## 可替换分析器

Python只依赖`JavaSemanticAnalyzer`端口和版本化JSON契约。默认本地Sidecar使用JavaParser与Symbol Solver解析源码根、重载、继承、接口分派、注解和枚举构造绑定；解析器专有类型不进入领域模型。未解析边保存原因和低置信度，现有确定性扫描只补充明确缺口，不建立第二套重复调用图。

公共逻辑只收录跨两个以上知识入口复用的业务符号，或具有状态机、责任链、事件链明确结构证据的符号。状态机、责任链等使用相同`logic:<symbol>`节点，以分类元数据投影到`公共逻辑`目录。

## 状态标签

枚举常量保留稳定code。分析器输出类型级和常量级Javadoc摘要，并从声明字段、构造参数赋值和getter绑定中选择`name`、`desc`、`description`描述。逐值含义优先采用有效常量Javadoc，其次使用唯一构造绑定，最后回退稳定code；类级业务注释可用时作为名称，否则暂用Java枚举名。注释或代码标识形成`CODE_DEFAULT`，表示“代码默认、可人工修订”，不会冒充`USER_CONFIRMED`。

## 问题周期

访谈规划器先消费代码事实、四项核心背景和业务术语，再把仍无法判断且影响业务行为、责任边界、异常结果或测试判断的开放问题固定为一个`KnowledgeQuestionCycle`。周期绑定系统、不可变`scan_id`、问题集合摘要、逐题暂存答案和本地重算任务；前置关系只用于解释与排序，不隐藏已发现问题。历史`question:business-name:*`、枚举维护、技术辅助方法、类名翻译和调用链已能证明的用途不得进入新周期。问题保留分类、优先级、提问原因、影响目标和源码证据，相同疑点跨目标合并并复用稳定历史答案。

单题保存只更新Git忽略的本地周期文件，不写`USER_CONFIRMED`，也不触发分析。所有问题均有答案后，用户通过“完成本轮并重新分析”统一确认；“暂不确定”算已填写，但转为持续显示的受影响知识与测试阻塞项。优先级、分类和当前对象筛选只改变可见卡片，不改变整轮完整性。

右栏在完整周期之上提供“未填写 / 已填写 / 全部问题”三个Tab，默认未填写。“已填写”只计算当前周期非空暂存答案，包含“暂不确定”；保存后问题立即迁移到已填写。Tab与范围、优先级、分类筛选共同决定可见卡片，但问题徽标、缺答数量和完成门禁始终按整个周期计算。系统或周期变化时重置为未填写。

完成动作校验系统、周期ID、问题摘要、最新Manifest指针和当前源码基线。问题或源码变更返回稳定stale冲突，新周期仅继承稳定问题ID仍匹配的暂存答案。完成后复用周期Manifest执行本地知识重算，不重复源码全扫描，不调用Agent、QA或业务接口；任务失败保留原周期和答案，进入可幂等重试的`BLOCKED`状态。历史周期按ID保留，使重复完成在新周期生成后仍返回首次任务。

## 代码事实吸收

候选保持原稳定ID、`kind`和存储路径，并用`knowledge_form`区分普通术语、业务枚举和外部应用。业务枚举分别保存业务名称及来源、结构化code/含义/来源/置信度/证据；`CODE_VERIFIED`表示唯一构造绑定，`CODE_DEFAULT`表示注释或代码标识提供的可修订默认值。枚举不进入集中问答周期：注释缺失、同名类型或常量回退均保留明确代码来源并直接展示，避免把逐项维护成本转移给业务用户。重扫刷新代码默认值但保护`USER_CONFIRMED`人工名称和值；同名类型冲突使展示code变化时按值级全限定源码符号迁移人工含义，无法唯一匹配则保留原值并转为复核。候选合并后重新执行严格模型校验，纯代码状态不得混入人工值、已知未知或缺少值级证据的来源。旧YAML按兼容默认值读取，并在下一次语义发现时迁移为业务枚举而不改变ID、人工回答或历史状态。旧枚举问题周期在下一次读取时因问题摘要变化转为`STALE`，无需重新填写。

语义Sidecar同时输出类型的直接字段引用与集合标记。页面只把直接声明关系作为核心对象问题前提，不从字段推断业务所有权、生命周期归属或未证明基数。

## 三栏工作台

知识库顶部以既有视觉体系展示四步流程条：完善背景、生成知识、确认疑点、使用与修订。流程条根据持久化事实投影完成、当前、待处理、部分失败和知识过期，不建立第二套状态机；同时展示当前Agent、已处理目标数、活动或最近任务以及唯一下一步操作。桌面横向展示，390×844使用四列短标签并在下方解释当前步骤。

左栏组织业务背景、接口文档、公共逻辑、业务术语、业务枚举和外部应用，并固定提供“全部待确认问题（N）”。普通目标被选择后，右栏立即切换为当前对象范围；全部问题入口在中栏展示周期概览并让右栏按每页20项渐进渲染。业务枚举为单层列表，以类注释或Java枚举名形成的默认名称为主标题、Java符号为次级标识，并逐字段显示`CODE_DEFAULT / CODE_VERIFIED / INFERRED / USER_CONFIRMED`来源。中栏展示已经发布的确定性事实、Agent代码解释和人工知识，未确认修订草稿只在右栏出现。从背景、接口或公共逻辑进入术语、枚举或应用详情时保存轻量返回栈，返回恢复原知识、聊天、问题对象筛选和移动抽屉状态；系统或扫描周期变化时清空。

业务背景详情允许显式保存系统定位、核心对象、成功主流程、上下游责任边界和原有其他背景答案，也允许新增、修改或删除业务术语。四项核心背景非空且不是“暂不确定”时，用户首次点击“背景与术语已完善”写入永久完成时间；后续编辑不重新打开步骤1，也不自动调用Agent。系统级背景变化把全部知识标记为过期；术语变化优先使用`affected_target_ids`精确标记，无法定位时保守影响全部目标。旧知识仍可浏览，用户需重新显式选择Agent和范围后更新。

页面只允许对当前选中的一个目标生成知识，暂时下掉“生成全部”；公开`target_ids`始终只保存该目标，但后端在启动Codex前沿已解析调用边确定可达公共业务方法、精确`setState`状态流转及Actor业务逻辑，并把未完整生成的依赖节点加入同一批次的`candidate_node_ids`。多个用户目标在创建任务前拒绝；完整且属于当前scan的`INFERRED / USER_CONFIRMED`依赖在没有开放问题时只连边不重写，缺失、`CODE_ONLY / STALE / FAILED / HAS_QUESTIONS`或子节点不完整时与主接口一起生成并原子发布。方法体定位先屏蔽注释和字面量，再区分类型与方法声明、跳过更早调用点并配平参数和正文；方法或构造器声明不计作调用或副作用，源码引用复用真实声明偏移。合法入口仅能证明方法存在时发布明确边界的最小`CODE_VERIFIED`事实，不因内容较浅提问。目录清楚区分未生成、生成中、已生成、仅代码事实、待确认、已确认、已过期和生成失败。

## Agent选择与逐目标生成

Git忽略且固定0600的全局本地设置保存`knowledge_agent = "" | "codex" | "claude"`、Sol或Luna、`low | medium`和唯一业务Prompt模板；新设置、省略字段和页面无有效配置时统一默认`gpt-5.6-luna / low`。现有运行设置页允许编辑业务目标、深度、章节和示例要求，展示白名单变量、默认恢复及当前目标完整合成Prompt；系统固定追加handoff身份、工具、安全、目标绑定、输出Schema和补全协议。每个任务保存模型、档位、模板摘要和最终Prompt快照，后续配置修改不影响已运行聊天。Codex的“生成/重新生成”点击本身即授权创建一个客户端聊天并在该聊天内连续分析、补读、修正和重提候选，不再追加逐轮费用确认；页面仍说明从客户端发送消息开始按正常Codex使用计费。Claude Code暂时保留既有流程但本轮不扩展。

后端只执行请求指定且与全局选择一致的Agent，不得自动选择、跨Agent切换或兜底。Agent不可用时阻止提交。单目标任务依次执行确定性源码追踪、指定Agent只读分析、严格输出校验、按来源发布和结果检查点：确定性事实为`CODE_VERIFIED`，Agent代码解释为`INFERRED`，用户后续确认才是`USER_CONFIRMED`。指定Agent失败时保存确定性事实并标记`CODE_ONLY / Agent失败`；确定性追踪也失败才标记`FAILED`。

Agent不再只接收入口源码窗口。Runner保持Shell、原生文件工具、网络、浏览器、用户MCP、插件和多Agent关闭，仅注入OpenTest自带的`list_source_files / search_source / read_source`三个stdio工具；工具以任务注册源码根为唯一读取边界，拒绝绝对路径、`..`、逐级符号链接、QA、Fixture、测试和构建目录及其文件名、连字符、驼峰和大写缩写变体，并限制文本类型、文件大小、结果数与单次读取行数。搜索采用线性字面量匹配，疑似认证配置命名直接拒绝，认证赋值行只返回脱敏占位。Facade遇到`execute`、服务枚举或代理动态分发时，Agent必须继续定位注解绑定的Validator/Invoker/Provider，再进入核心Service以及首个DAO/Mapper或远程边界；公开接口方法和对应同名实现方法均可作为首个entry，边界后的Service/Invoker返回组装可以继续列出。依赖范围由代码扫描固定，Agent必须逐项覆盖全部`candidate_node_ids`且不得新增、删除或替换节点。Agent声明的全部源码引用和引用行必须位于本次实际`read_source`区间，合法引用追加到发布节点，访问轨迹以不含源码正文的0600 JSONL保存。

供应商结构化输出使用专用严格信封：节点摘要为`[{node_id, summary}]`，源码引用只包含`path / symbol / line`，执行路径使用有序`trace_steps`标记`entry / invoker / service / data_access / remote_boundary / no_downstream`及对应源码引用；所有字段显式必填、空集合使用`[]`、未知行号使用`null`，每个对象均关闭额外字段。Facade完成结果的前向核心路径必须从请求入口到达可识别的核心Service和首个DAO/Mapper/Repository数据访问或Client/Gateway/Proxy远程调用；边界后的返回组装不要求角色继续单调递进。完整度章节只拒绝空白、明确占位和复制/高度重复内容，不使用字符数门槛。不得把Invoker、Service或未经证明的`no_downstream`冒充完整路径。Runner在创建运行目录和启动供应商进程前递归拒绝缺失`required`、动态Map、未关闭对象、非对象根和供应商不支持的组合关键字，Codex与Claude Code共用同一预检且互不兜底。Agent失败而确定性事实已发布时，任务以`partial`结束并分别累计Agent与确定性失败；旧版误记`completed`但outcome含`safe_error`的任务只在读取时兼容投影，不改写原证据。

Codex新生成先以`model/list`验证任务固化的Sol或Luna及页面档位，默认组合为`gpt-5.6-luna / low`，再使用App Server以`approvalPolicy=never`、只读沙箱创建持久客户端thread、命名并只注入首条任务历史；不支持时在创建费用前拒绝且不自动换模型。App Server进程在创建或官方`thread/read(includeTurns=true)`只读检查结束后立即关闭，OpenTest不得调用`thread/resume`、`turn/start`或保持后台生成进程。页面获得thread后先打开`codex://threads/<id>`，再幂等调用`/knowledge/client-handoffs/{handoff_id}/turns`；桌面深链完成会话load，本机桌面桥接通过同用户、权限受限的Unix套接字执行版本化owner discovery，并只向当前owner发送`thread-follower-start-turn`。响应明确返回`started / already_started / manual_required`；IPC不存在、版本不匹配、没有owner或桌面拒绝时只提示用户在原Codex任务手动发送开始消息，禁止退回App Server写入。

请求以`interaction_mode=codex_client`、`intent`和`attempt_id`绑定幂等handoff、任务、目标、扫描、模型、模板快照和草稿批次；首轮、自动补全、人工回答和历史恢复都复用这些身份及原thread。全仓库以跨进程锁和持久批次状态保证任一时刻最多一个`waiting_for_client / waiting_for_input / waiting_for_confirmation / rejected`的Codex知识聊天，新目标必须等原聊天完成、失败或取消。仓库插件通过回环HTTP桥接任务读取、三个受控源码工具和候选提交；不再提供逐候选确认工具。安全校验失败立即拒绝；机器内容缺口返回精确`completion_gaps`并保持`waiting_for_client`，系统在最近turn意外结束时由桌面owner在原任务自动续跑，不设置补全轮次上限。handoff保存最后处理turn ID、续跑候选摘要、缺口集合和无进展计数；只有连续两个已结束turn的候选摘要及缺口集合完全相同时才停止模型调用并进入明确技术失败。历史`waiting_for_completion`只做兼容反序列化，首次协调时原地迁回`waiting_for_client`。完整候选自动复用原发布、基线、索引和关系事务，仍保持`INFERRED`，不得升级为`USER_CONFIRMED`。Codex增量响应保留在客户端，OpenTest只展示生成中、自动补全、等待用户回答、已发布或技术失败，以及源码轨迹、补全缺口、问题和最终知识。

接口类型发布节点可携带结构化`invocation_contract`，与节点共享版本、目标、扫描和发布事务，但不写入Markdown自动正文、普通FTS、关系推荐或知识问答上下文。只有扫描读写属性或保守查询方法语义明确证明为只读的入口才生成契约并进入能力索引；写入或读写未知入口仍可保存业务知识，但契约必须为空。扫描确定`tool_id`、请求响应类型、传输路径、请求模板、必填字段及只读属性，Agent只能补字段含义、日期维度、枚举、分页、错误和示例；稳定字段被改写属于安全错误。独立能力索引只在上层已经识别“查询、调用、执行”工具意图后读取契约，因此“接口做什么”或业务术语问答不加载契约。带日期但维度不唯一时合并追问创建、申请、出发或更新时间；能力解析本身不执行接口，凭证和原始敏感响应不得进入Prompt、知识或日志。

Agent返回`needs_input`时必须至少包含一个具有真实源码引用、明确影响节点和目标、影响为high的问题。系统立即发布不受问题影响的确定性代码事实，暂缓未完成推断并把结构化文本、单选或多选问题放入当前对象右栏和任务卡；Codex客户端handoff进入`waiting_for_input`且继续占用原聊天身份。用户点击“在Codex中回答”回到原thread直接回复，不创建新task、handoff、thread、batch或scan，也不追加普通完整度确认；同一聊天提交不含开放问题且通过门禁的`completed`候选后自动发布。非客户端Agent仍复用既有问题周期和原session续跑契约。页面或SSE重连只读取原事件；服务重启只恢复持久身份和只读检查点，不得静默创建第二次付费调用。

工作流快照显式投影按目标排列的`generation_attempts`以及活动任务ID、当前目标、实际Agent、任务状态和阻塞原因。任务卡、事件、诊断、handoff和知识正文始终按`system_id + target_id + attempt_id`选择，禁止回落到系统最近的其他接口。页面刷新只用这些检查点恢复原SSE或Codex深链；`pending / running / waiting_for_client / waiting_for_input / waiting_for_confirmation`以及兼容读取的`waiting_for_completion`都禁用该目标的新尝试。提交函数在创建前再次检查全仓库持久化活动状态，同一`attempt_id`幂等返回原任务，任何系统、刷新、重复点击或并发请求都不能创建第二个聊天或付费调用。

目标详情页面使用轻量响应，不重复执行完整`list_questions()`和`get_context()`；关联问题由前端从已加载周期筛选。选择目标时同一帧清除旧正文并显示带目标名的中栏骨架，主动取消旧GET并以选择代次拒绝迟到响应；固定扫描目录和基础详情可缓存，扫描、背景、发布或索引变化时失效。问题周期普通读取返回持久化快照，只在扫描、生成、回答或修订后显式重算。失败只显示新目标的常驻错误和重试入口，不得恢复其他接口正文。

## 修订式知识聊天

中栏底部保存绑定当前背景、候选、接口或公共逻辑的聊天历史。只有用户点击“发送并分析”或重试时才运行现有本地只读Agent；请求不包含QA、Fixture或敏感设置，Agent只收到固定Manifest、已确认知识、当前作用域证据和用户消息。Agent输出必须通过严格结构、系统、扫描、作用域、源码证据和精确前后值校验，且不能产生`CODE_VERIFIED`或直接修改知识。背景和候选口径可声明`USER_MESSAGE`证据，节点源码修订必须声明`SOURCE_REFERENCE`且至少选择一条当前作用域规范引用；Agent提供的repository、commit和内容摘要一律替换为服务端固定引用。

合法的背景更新、候选新增、候选修订或节点修订各自转换为`source=conversation`的右栏固定选择题：“确认发布 / 暂不确定”。确认卡由服务端确定性展示写入目标、真实before/proposed逐节点差异和证据基础，不采用Agent自述标题或详情。同一信封、现有开放问题和其他未决会话不得争写同一背景问题、候选或节点。每项提案的发布摘要只绑定其真实背景项、候选或目标节点依赖，使不同写目标的未决会话可独立收敛；同一Agent信封中的后续提案只按各自依赖安全重基。

完成周期时不调用Agent，并优先应用会话问题；确认发布才在系统锁内应用人工知识并重建必要索引，暂不确定不发布。多节点发布记录`not_started / partial / published`并只续写仍精确等于before的节点；部分恢复只归一化本提案已经精确写入的正文和原状态，所选目标内其他变化仍返回稳定stale。节点正文全部落盘但索引重建失败时，重试必须再次幂等重建索引，成功后才能记录发布终态。知识、Manifest或前值变化返回稳定stale冲突。Agent不可用、非法输出或信息不足时保留消息为`BLOCKED`且允许显式重试，不生成猜测问题。新消息只取代同一作用域未确认提案，其他问题和稳定暂存答案继续继承。

## 本地存储

Git知识文件继续保存人工含义、答案和已发布正文；Sidecar结果、问题投影和调用边摘要保存为可重建派生资产。未确认的周期与暂存答案保存在`.opentest/knowledge-question-cycles/<system>`的0700目录和0600文件中，会话轮次与提案保存在`.opentest/knowledge-conversations/<system>`的0700目录和0600原子文件中，并随系统归档。旧Manifest、缺少类型关系的语义结果、问题和知识节点使用兼容默认值读取，人工内容不因重扫被覆盖。

## 知识所有权与任务归档

语义方法身份使用全限定类名、方法名和全限定参数类型，签名变化形成新身份。公共逻辑的复用计数按不同知识所有者计算，同一入口内多个调用点仍属于一个所有者；只有至少两个入口或状态流转共同引用且具有可测试业务行为的方法投影到公共目录。状态机与精确状态流转始终拥有自己的业务细节，Actor方法只有跨知识复用时才成为公共逻辑。入口正文保留入口条件、编排影响和关系链接，不复制公共节点或状态流转的详细分支。

`.opentest/tasks`只保存活动任务，`archive/`保存Codex handoff终态JSON。服务启动、任务进入终态及同目标创建新任务前都执行归档；按ID读取同时搜索活动和归档目录，普通列表只扫描活动目录。知识目标详情按`system_id + target_id`返回安全历史摘要和Codex深链，因此归档不影响诊断或跳转。
