# Change: Java语义知识与三栏工作台

## Why

现有知识发现主要依赖正则枚举和外部应用候选，首轮问题缺少系统定位、核心对象、流程边界和测试Oracle；调用追踪无法可靠去重跨文件公共逻辑，状态机只展示枚举常量；知识正文和问题列表还在同一内容区重复出现。最低底线知识流程还缺少明确步骤、Agent费用选择、全范围Loading和可恢复的逐目标检查点，并会把源码可判断的接口口径重复抛给用户。

## What Changes

- 增加可替换的本地Java语义分析器，输出调用边、公共逻辑、模式证据、类型/常量Javadoc和枚举展示名。
- 使用证据驱动问题周期生成系统级和对象级问题：当前周期全部展示、逐题暂存、显式完成后统一重算。
- 将枚举建模为独立“业务枚举”，常量注释优先形成可人工修订的代码默认值；缺少注释时回退唯一构造描述或代码标识，不再生成枚举维护问题。
- 扩展问题、状态标签和知识目标契约，保持Git真相与SQLite派生索引。
- 将知识页改为目录、当前知识和待确认问题三栏工作台。
- 中栏只读展示已确认背景、术语、外部应用和代码事实；用户通过显式修订聊天形成右栏待确认提案。
- 将知识库收敛为“完善背景、生成知识、确认疑点、使用与修订”四步，背景首次完成后仍可显式编辑并把受影响知识标为过期。
- 知识生成必须使用用户全局明确选择的Codex或Claude Code；提交前显示Agent、范围、只读边界和费用提示，后端不得自动选择或跨Agent兜底。
- 知识生成一次只处理一个当前对象；本地Codex JSONL或Claude Code stream-json事件持续保存并通过SSE展示，右栏只保留源码与背景仍无法判断的高影响疑点。
- Codex客户端知识生成允许页面选择Sol或Luna及Low/Medium，省略配置和新本机设置默认`gpt-5.6-luna / low`，全仓库最多一个未结束聊天；全局业务Prompt模板可编辑和预览，固定安全协议不可编辑。
- 单接口生成在启动Codex前由代码扫描确定可达公共业务方法、精确状态流转及Actor逻辑，按当前scan知识状态形成稳定候选清单；Agent只补全清单内容，主接口与缺失依赖在同一task、handoff、thread、batch和scan中原子发布。
- Facade候选必须通过安全与内容完整度门禁；机器可修复缺口在同一任务和聊天中持续自动补全，只有连续两个已结束turn产生完全相同的候选摘要与缺口集合才作为无进展技术失败；完整候选自动发布，不再逐候选确认。
- Codex桌面端是活动知识会话的唯一writer。OpenTest只创建无turn持久thread、只读轮询状态并通过同用户本机桌面IPC请求owner启动turn；IPC缺失或版本不兼容时仅提示在原任务手动开始，不得由OpenTest恢复会话并抢占writer。
- 真正需要业务判断的`needs_input`候选进入同一handoff的`waiting_for_input`，先发布不依赖答案的确定性事实，并在任务卡展示有源码证据的高影响问题；用户在原Codex任务回答后继续提交最终候选。
- 接口调用契约作为发布节点的隔离附属结构和独立能力索引保存，不进入Markdown正文、普通FTS、关系推荐或普通知识问答上下文。
- Agent执行不设固定分析超时并关闭标准输入；页面断线只续传事件，不重复付费调用，服务重启优先接管原工作进程和会话检查点。
- 目标详情使用不重复加载完整问题和上下文的轻量模式，全部问题按20项渐进展示，并为查询、操作、失败和恢复提供明确状态。

## Scope

一期支持Java项目、本地分析和桌面/移动控制台，不部署图数据库或远程代码索引服务。

## Non-Goals

- 不声称反射、动态代理或缺失依赖调用已确定解析。
- 不把所有getter、setter和简单映射加入公共逻辑。
- 不依赖用户安装`grilling` skill。
- 不增加第二个知识页面或问题状态机；背景与术语在既有业务背景详情内显式编辑，知识正文和修订草稿仍不得绕过右栏发布门禁。
- 不把代码事实冒充`USER_CONFIRMED`，也不因用户筛选问题而缩小整轮完成范围。
