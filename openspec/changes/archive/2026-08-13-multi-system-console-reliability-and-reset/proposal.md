# Change: 多系统控制台可靠性与混合数据重置

## Why

当前知识存储和控制台仍把一期“单系统”约束当作运行时实现：注册第二个系统会被拒绝，更新会重写整个注册表，页面也只读取第一个系统。由此已经发生 `train-booking-core` 的源码路径被退款项目覆盖，而扫描、知识、资源和 Case 仍属于 Booking.Core 的混合状态。与此同时，scriptgen 只在 Uvicorn 启动时读取环境变量，表单和长任务缺少可靠门禁，扫描树与资源状态也会混入历史系统数据。

## What Changes

- 将系统注册表升级为同仓库多系统工作区，保持系统内知识、Case、资源和任务严格隔离，仍不建立跨系统关系。
- 提供带摘要清单的可恢复归档和恢复机制，将当前混合知识与本地数据归档后清空活动系统。
- 增加 Git 忽略的本地运行设置，动态解析并诊断 scriptgen；无效时阻止扫描任务提交。
- 增加 QA Facade 网关前缀和只在浏览器组合 Token 的 Curl 示例。
- 增加全局排他任务状态，统一表单校验、Toast、短操作 Spinner、长任务全屏 Loading 及刷新恢复。
- 重构系统列表/切换、可折叠导航、分层扫描目录、状态筛选、知识快捷入口及当前源码资源投影。

## Scope

本 Change 修复多系统隔离、当前混合数据、扫描运行设置和控制台可靠性。它不生成新的业务知识、不执行真实创单，也不放宽 Worker、TiDB READ 池或 QA 环境门禁。

## Non-Goals

- 不创建跨系统知识关系、跨系统 Case 或跨系统资源引用。
- 不永久删除当前混合数据。
- 不在 OpenTest 内发送页面生成的 Curl。
- 不把 Booking.Core Worker 作为任意新系统的通用校验器。
- 不归档仍等待真实 QA 输入的 `dsf-execution-and-oracles`。
