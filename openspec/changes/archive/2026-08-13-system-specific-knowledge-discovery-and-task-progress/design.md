# 系统专属知识发现与全局任务进度设计

## 知识上下文真相与兼容

每个系统在`systems/<system_id>/context.yaml`保存用途、上游说明、术语和外部应用候选，在`questions/questions.yaml`保存统一问题。旧本地`KnowledgeInterview`继续作为迁移输入和兼容API存储，但V2页面只使用新接口。首次读取时把旧用途和上游数组合并到新叙述字段；旧下游、分单字段和固定术语不会自动迁移到普通系统。

候选ID由`system_id + kind + normalized symbol/name`生成，重扫按ID合并。人工含义、确认/忽略状态和答案优先保留；证据摘要变化把已确认项标记为`NEEDS_REVIEW`；本轮未发现的自动候选标记为`STALE`。每次读写都校验候选、证据和影响目标属于当前系统。

## 确定性发现与Agent边界

Manifest发布后先以当前系统的Facade、Job、状态机、MQ、外部调用、DTO/枚举及源码证据生成确定性候选。可用时再让本地Agent补充严格结构化候选；Agent只接收当前源码根、Manifest证据和该系统已确认上下文。未知目标、其他系统ID或越过源码根的证据被确定性拒绝。

发现是扫描任务的独立后置阶段。扫描Manifest发布成功后即视为扫描成功；发现失败记录`TaskWarning`和可重试动作，不把注册或扫描任务改成失败。

## 统一问题投影

统一问题视图聚合四类来源：缺失的用途/上游说明、开放候选、知识草稿问题和知识修订问题。问题ID携带稳定来源标识，回答写回对应真相并触发受影响目标重新生成或标记待生成。聚合前验证系统范围，禁止把一个系统的答案传播给另一个系统。

## 任务进度

`TaskProgressReporter`以任务ID绑定持久化记录，提供阶段、阶段序号、处理数量、当前项、提示与警告更新。任务线程中的更新通过任务管理器锁原子写入；`/console/activity`直接投影最新任务进度，页面刷新后继续轮询。

未知总量时`item_total`为空，页面显示阶段Spinner；已知总量时显示真实`completed/total`。终态由任务管理器统一补齐，业务函数不得伪造100%。旧任务JSON缺少新字段时使用兼容默认值。

## 知识目录与页面

知识目录按`Facade → 类 → 方法`、`Job → 业务域 → Job`和`状态机 → 名称 → 流转`组织，分类和分组默认折叠。选择叶子只加载目标详情，不自动调用Agent。主编辑区显示面包屑、状态、源码证据、最新草稿、已发布正文、关联问题和绑定目标的反馈输入。

Booking.Core专属面板只在系统ID严格等于`travelsystem.java.dsf.supplychain.booking.core`且扫描能力匹配时渲染；通用追踪器也必须同时满足系统ID和目标符号，不能只按`TradeFacade#createOrder`名称分流。

## 安全与兼容

- Token、Fixture、QA配置和QA结果不进入发现输入、任务进度、知识文件或日志。
- 旧访谈、同步Case和自然语言接口保留兼容；V2控制台改用新异步入口。
- SQLite仍是可删除重建的派生索引，候选和回答只以Git知识文件为真相。
