# Change: Deterministic Agent Hybrid Case Lifecycle

## Why

Program analysis currently promotes unbound internal calls into mandatory business gaps, entry knowledge cannot express stable entity prerequisites or products, and the Case workspace exposes pipeline IDs and error codes as its primary user experience. This produces false blockers while still requiring users to supply runtime business identities manually.

## What Changes

- Classify program findings into nine condition kinds and freeze only true input-coverage obligations into the combination denominator.
- Extend existing knowledge nodes with assertion-level entry facts and isolate AI candidates from formal knowledge.
- Extend existing Setup Fact and Recipe assets for state predicates, recursive producers, deterministic query availability/extraction, relation guarantees and dependency cycles.
- Compile formal entry requirements into an immutable stateful Setup DAG without QA access; execute it only after explicit user action.
- Project generation, readiness, execution and finalization separately and provide one shared business-facing status model.
- Drive the Case directory from every real latest-scan Facade, MQ and Job entry and load compilation details on demand.
- Replace the obsolete mandatory matrix-confirmation write flow with deterministic formal-asset generation.

## Compatibility

Program analysis V1 and Setup Recipe V2 remain identity-only read-only assets. They are never reinterpreted under the new semantics. Historical Runs, user-edited Cases, custom Cases, old matrices and immutable Generations remain unchanged.

## Scope

The first executable condition is `STATEFUL_ENTITY_PRECONDITION`. Other condition types are classified and prevented from creating false pairwise coverage; unsupported execution requirements remain explicit. The change reuses Published Capability, Setup Fact/Recipe, Hybrid Generation, QA Worker, Oracle and Cleanup assets.

## Out of Scope

Files, images, quotes, tokens, login sessions, MQ-event facts, snapshots, resource pools, leases, distributed locks, schedulers, retries, background compensation, graph databases and a general workflow engine are excluded. Generation never accesses QA, AI never produces real business IDs, and execution never asks AI to alter the frozen graph.
