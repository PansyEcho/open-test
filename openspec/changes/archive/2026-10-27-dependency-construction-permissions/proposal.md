# Change: 依赖系统构造权限

## Why

当前“上下游系统”页面只展示扫描发现的关系和引用接口，无法表达构造 Case 时可以调用哪些接口、哪些接口会写入数据，也无法区分通过应用写数据和直接写数据库。结果是用户无法在生成前合理授权，Agent 只能在失败后暴露缺口。

## What Changes

- 按 canonical provider system 归并上下游，同一系统的上游/下游共用一份权限；`dsf.` 只作为通道名，不作为权限主键。
- 增加依赖系统构造权限：接口逐项开关，支持一次开启当前已发现的全部接口；源码扫描和数据库直连权限独立，保留已有只读授权。
- 未解析的外部引用只展示原始通道和引用证据，必须解析登记后才能授权和调用。
- 页面按系统折叠加载，展示“已授权 + 引用/全部”接口，按 Facade/类分组；批量开启包含写接口，不联动数据库权限，也不授权后来新增接口。
- 权限按员工、当前系统和环境保存；Case 使用固定扫描能力并在实际调用前重新检查权限。

## Non-Goals

不引入生产环境写权限、不绕过 Operation/数据函数执行器、不因关系发现自动授权接口或数据库删除权限。
