# 实现决策
- 查询成本由固定页面投影决定，不随历史Manifest数量增长。新增投影只写已有ot_scan.summary_json，消费方是控制台目录/资源；首次无本机缓存时也不用下载扫描包。
- 数据库读连接复用成熟组件，最多4条；仅无外层事务的SELECT使用读池。写入、FOR UPDATE和GET_LOCK继续沿用独立事务连接，finally物理关闭。
- 保持原完整接口供Agent和详情消费；列表显式view=summary，默认20、最多100条，提供翻页信息。
- 状态更新由已有revision/扫描身份检查失效，任务轮询直读；缓存不替代业务执行校验，不重试未知结果写入。
- 兼容迁移显式运行，补齐扫描展示投影并规范化既有背景。GET不隐式迁移或锁系统行。
- 验收采用10个独立进程与缓存、共用MySQL；完整冷读和10分钟热负载分别统计，不把错误或缺字段响应当作达标。
- 十工作台冷读复现了后台恢复每5秒下载全部历史任务的持续带宽争用。恢复查询改为数据库筛选本workspace且web_run_active的任务，再附着原进程；不改变任务执行所有权。
- 对确实较大的背景、扫描投影、精确契约/Case/Data与工作流详情使用MySQL COMPRESS无损传输，原表与JSON模型保持不变；不是新增缓存或持久压缩副本。
- 精确目标的历史草稿只查询匹配的ID和时间，在应用内选最新，避免MySQL将含大型JSON谓词的行带入filesort而耗尽排序内存。

- 整页并发冷读证实完整context的72/82个候选占用约558/390KB，其中大部分为未打开候选的枚举及证据。浏览器context summary保留全部背景和候选显示字段；点击候选再按ID读取完整证据，原全文接口保持不变。背景页面直接使用context事实，不重复读取未展示的旧长文目标。
- 工作流summary直接读背景完成标记、入口身份与契约状态；不依赖完整context和目录。任务摘要集合无损压缩，减少十工作台同时冷读的传输。
- OCR初审发现四项Medium（筛选后分页、环境保存迟到响应、任务翻页身份、契约详情状态），均接受并修复；候选分页不影响固定Case及执行前验证。

- 系统配置整页测试进一步定位归档列表仍下载完整文件清单，改为已有工作流表摘要分页；恢复保持原完整性校验。Case用例页保留完整DSL和批次摘要，隐藏的执行结果页签不自动读取约1.7MB报告，打开结果时单独验证全文时延。

## 最终验收记录（2026-09-29）

### 方法与范围

保留现有远端MySQL，使用10个独立Uvicorn进程、独立workspace身份和空本地缓存，连接同一测试数据库。读池每进程最多4条，写事务使用独立连接；40条上限仅指读连接。现有booking和refund系统均参加验收。使用真实同值配置保存触发事务及共享版本失效，不改业务名称、Git基线或固定Case，不调用被测业务接口。

改造前为单工作台的单次HTTP测量；改造后是10个工作台的分端点P95和最大值，不能把两者当作同条件平均值对比。任务、Case版本、共享数据与工作流的浏览列表已改为摘要，完整对象另按ID验收。冷读从空缓存开始，但同一工作台顺序访问时允许复用之前已完成的读；因此另外用全新进程测量整页并发冷读，避免只验证缓存命中。
