# Decisions

- MySQL保存共享业务真相，13张聚合表保留现有模型JSON；完整扫描与执行详情压缩存储，列表只读取摘要。源码仍由Git保存，快照按完整commit解析。
- 源码与工具绝对路径仅属于工作台；共享扫描工具按相对路径打包。系统配置、凭据、扫描规则和工具路径继续文件。
- 接口记录按scan/operation固定，契约revision只追加；当前关系索引可重建，历史Generation内嵌选定操作和版本不随latest更新。
- 发布使用短MySQL事务与目录行锁，耗时扫描、AI和业务执行不持有事务。Operation请求保持跨系统去重，数据请求保留系统命名空间；历史无request_id记录使用NULL。
- 工作台本地workspace_id标记活动任务和执行的所有者；只处理本机孤儿任务，不引入远端自动接管。
- 程序覆盖复用现有JavaParser、调用图和义务模型。先适配实际MyBatis XML、CacheClientHA、SOF Producer、DSF和事件监听；未解析数据流与动态分派保留缺口。
- MQ及其他必要事件断言没有观察源时失败且分类为OBSERVATION_FAILED，不以路由或间接效果替代。
- 停写后一次性导入并回读校验，不长期双写。只在完全验证后切换共享存储；旧文件保留。
- 共享目录查询只取使用的JSON子结构；完整工作流按已读取的小时间键在本机排序，避免MySQL携带大JSON执行filesort时耗尽排序缓冲区。
- 含大型嵌套类型的扫描时接口投影复用scan_id本地缓存；后补resolved_operation和契约revision仍远程读取，避免不可变部分重复传输又不隐藏新补充。
- 旧文件中真实发生的重复Data请求完整保留，最近记录拥有去重索引；新Case的数据请求键包含本次执行身份，固定Variant跨执行复用不会冲突。

# Verification

验证MySQL真实读写与并发幂等、不同目录工作台的扫描与工具复用、关系双向补全和失效、契约无需重复扫描、AI覆盖遗漏、前后观察及缺失观察源失败。保持生产源码Case冻结与测试环境执行分离。
