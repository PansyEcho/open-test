# 实现边界

- 维护的裁剪待办由首次终态、报告首次终态或既有待办决定；专属任务仍 RUNNING 只意味着等待绑定业务结束，不能重新制造裁剪待办。
- 同名类冲突依据实际选中的分析材料。相同字节码可重复，不为此新增摘要算法；不同字节码给出 ARTIFACT_DUPLICATE_CLASS，不暴露归档敏感内容。JaCoCo 不统计的合法模块描述符不作为业务类冲突。
- 无快照旧扫描在启动阶段复用后续源码范围校验的基线比较口径；托管快照路径不受影响。覆盖默认版本的降级保留，并记录异常类型。
- 历史 Case 只作为补充生成参考，筛选相同系统、接口、QA、固定源码及契约、真实成功执行。查询有界，不读全部历史执行大包；异常记录隔离，历史不存在不阻断补充。
- 历史任务仅查看过但两边定义均未引用的额外接口，不决定 Case 兼容性；共同契约修订不同，或数据准备、断言、清理实际引用的契约缺失，仍排除该候选。
- 模型仍需确认历史场景适用于本轮，复用固定数据函数动态准备数据，重新编译并执行，不能复用历史订单/响应作为本次证据。不扩大唯一补充轮次，也不保证模型一定新增覆盖。
- 验收区分有效性：本地故障测试证明边界，真实 MySQL 证明事务，真实 QA 只报告实际观察到的覆盖效果。
