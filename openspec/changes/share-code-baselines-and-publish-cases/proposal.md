# 共享代码基准与员工草稿发布

## Why

各员工在本机运行 OpenTest 时，需要复用同一固定源码、接口知识和 Case，同时保持个人草稿及测试环境选择独立。现有系统级源码固定、无员工身份的工具入口和本机覆盖材料不能满足这一流程。

## What Changes

- 强制公司登录，统一浏览器、用户 MCP 与任务 MCP 身份；员工以 newWorkId 归属。
- MySQL 保存基准、个人草稿和当前发布指针；S3 兼容存储保存实际源码、依赖及覆盖材料。
- 新基准继承背景术语并全量生成接口知识，Case 为空；接口、Case 支持单项和全部显式发布。
- QA/UAT 冻结到任务，覆盖增强加入部署确认、本人详情、人工重试和永久材料保留。
- 迁移历史成果，先迁移页面和插件调用方再退役旧整批读取；历史不可用项允许明确处置而不删除原数据。
- 回归 Case 按具体业务入口分层组织，独立展示 Case、生成任务、执行记录及覆盖增强；生成阻塞直接报告，不等待用户回答，按独立接口契约准入而非旧知识正文，并统一页面选择状态。
- 生成任务按完整范围内的最近活动选取一条；局部场景缺口保留可用 Case 的部分发布能力，下游契约缺失与签名重载分别报告。

## Impact

涉及持久层、公司登录、源码及知识服务、Case 发布、覆盖链路、API、MCP 插件和控制台。数据表、事务、验收及本期边界遵循 [定稿开发计划](../../../docs/discussions/shared-baselines-case-publication-development-plan.md)。保留工作树已有修改，独立评审只覆盖本次差异。
