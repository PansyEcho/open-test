# 实施设计

以 [定稿开发计划](../../../docs/discussions/shared-baselines-case-publication-development-plan.md) 的第 3 至 13 节为数据结构、表字段、事务、迁移及验收设计。

## 关键决定

- 新增七张表并扩展五张现有表，不新增覆盖任务平台或文件式业务存储。
- 员工归属与执行工作台分离；本机内存登录及 MCP 凭据按各自生命周期校验。
- 个人草稿与当前共享指针分离；旧内容保留但不通过产品入口重新开放。
- 发布同步逐项短事务，复用工作流回执固定请求范围；外部调用与扫描不进入发布事务。
- 对象存储只发布上传完成的实际材料，使用标准 SDK 与 path-style；材料默认不过期。
- 测量锁为系统和环境，重试只属于原员工；未知业务结果不重放。
- 当前部署的隔离属于应用约束，不能阻止持有共享数据库和对象存储凭据者直接访问。

## 实施依赖

公司应用登记/回调和 newWorkId 字段契约按计划在真实登录验收前核实；UAT 网关与归档实物在对应联调前核实。缺失资料不得用伪造身份或 QA 回退代替验收，其他独立开发继续。

## 验证与交付

逐阶段完成最小相关验证，最终验证双用户、双机器、QA/UAT 和历史迁移闭环。所有代码遵循方法注释、日志上下文及参数设计要求；使用 OCR delegation 模式独立审查本次差异。完成前停止本次服务并检查 8788。

## 实际接入与切换

- 公司登录沿用 Demo 的公司授权策略和员工核验接口。默认回调来源为 `http://127.0.0.1:8788`，可由 `OPENTEST_PUBLIC_ORIGIN` 配置；浏览器和本机用户工具凭据一小时到期，服务重启后需重新登录。工具每次读取 `~/.opentest/credentials.json`，可由 `OPENTEST_CREDENTIAL_FILE` 指定本机路径。
- RustFS 使用知识目录父目录下的 `.opentest/object-storage.yaml`；endpoint、bucket、region、path-style 均可配置。凭据仅保存在忽略版本控制的本机配置中，本次不改变公司应用登记。
- 旧共享库必须先备份并停止旧写入客户端，再执行结构升级和历史回填。应用启动只读检查结构，未升级时明确拒绝启动，不偷偷执行 DDL。

以下从项目根目录执行。命令默认只读预览；核对后在相应命令末尾追加 `--apply` 才写入。两步按顺序执行，历史回填需要结构升级完成。

```sh
.venv/bin/python -m opentest.adapters.shared_schema_upgrade --knowledge-root open-test-knowledge
.venv/bin/python -m opentest.adapters.shared_history_migration --knowledge-root open-test-knowledge
```

历史预览中的未处置异常必须逐条修复，或明确提供 `--unavailable <原记录ID> --confirmed-by <员工newWorkId>`；该操作保留原数据，不能代替解决结构错误或本期功能缺陷。原源码可通过历史迁移命令的 `--source-baseline <基准ID> --source-repository <包含原commit的仓库>` 预览补传，再显式追加 `--apply`。缺少原始材料不得上传当前工作树冒充。

验收记录以 tasks.md 为准。公司策略接口连通、模拟公司边界的认证测试、HTTP 页面夹具以及隔离数据库演练，不等同于真实员工授权、真实 QA/UAT 业务执行或团队共享库已上线。

## 2026-10-22 评审修复决定

- 迁移仅合并同系统、同干净 commit 的扫描，脏扫描和缺少 commit 的扫描各自独立。因此首选扫描缺项本身不是源码删除或需复核的证据，应信任该组接口并集；仅独立契约缺失或实际契约依赖不一致继续阻断 Case，不覆盖显式 REMOVED。合成契约材料在重放时仍按有限材料处理。已保存的复核状态不会被重跑迁移自动清除。
- 员工显式发布经完整依赖校验的等价 Case 草稿属于有效复核：同事务清除影响状态，保留共享修订、指针和原发布信息；回执重放不重新清除后续影响。旧正文和 migration_requires_review 标记不参与独立契约准入；缺失或身份不匹配的契约仍不能放行。
- 旧记录的 NULL 员工归属原样保留，允许原工作台收尾但不能由登录上下文认领。批量发布仅把可识别的单项材料、范围和结构错误记为 BLOCKED，并先回滚该项事务；数据库或未知程序错误继续向上报告，不能掩盖未知提交。连接故障使用独立错误类型映射为 503，恢复后原请求可以继续；知识等价比较先校验两侧独立契约及固定身份，旧正文不影响批次或兼容判定。
- 基准创建提交返回立即补任务关联；若关联前中断，先从既有任务查证，确无任务且同工作台原提交进程已退出才允许续跑。该进程证据使用既有任务管理器身份及请求回执，不新增表或队列。
- 普通 Cookie/用户 bearer 会话仍在内存；任务活动和私有归属查询交给框架线程池，并在慢查询后重验凭据是否已撤销。任务凭据继续随任务生命周期失效，不另加任意固定时限。插件使用安装目录相对路径并转发自定义凭据位置。
- 本轮不为可接受的无效 Cookie 拒绝、预览随机临时 ID、退役路由 reason_code 或未证明有功能影响的旧代码扩大改造；真实鉴权与 QA/UAT 验收按用户要求待回公司后继续。

## 2026-10-22 内网联调发现

- 天网容器日志的 `ip` 可能是容器名，`serverIp` 才是实例地址；实际 QA 部署页面和只读 JaCoCo dump 已交叉验证该字段。发现器优先校验 `serverIp`，仅缺失、null 或空串时兼容旧数字 `ip`；显式非法地址不能回退掩盖错误。保留应用、环境、时间窗口、完整分页及配置端口约束，不新增手工地址入口。
- 实例发现成功不等于部署材料匹配；覆盖测量仍需对应部署版本的实际字节码和源码。历史聊天中的登录参数不作为本机正式凭据配置，也不能据此默认取得复用授权。
- 用户再次确认日常交互只有部署版本确认，确认后取材由程序完成；FTP 不构成必需协议。现实现仍直接消费固定 `archive_version` 或本地包路径，自动按基准和实际部署定位构建产物尚有缺口，不能以补一组下载凭据代替完成该能力。钥匙串存储仅为讨论建议，尚未实现；不为解决本次材料问题先行增加凭据管理平台。
- 本期按用户选择使用公司 FTP；凭据读取 `${ENV:OPENTEST_FTP_USER}` 和 `${ENV:OPENTEST_FTP_PASSWORD}`，不把真实值写入共享配置。归档遵循 `<root>/<appUk>/war/<环境>/<版本目录>/<完整commit>/*.war` 与 `<root>/<appUk>/<环境>/<版本目录>/<完整commit>/out.tar.gz`。天网只提供实例和 appUk，不提供构建版本；普通版本点号转短横线仍须核对真实目录，不能猜测特殊版本规则或在同 commit 多构建时随意选取。
- 用户已确认当前 QA 候选目录存在。自动定位复用现有 FTP 读取器，只在当前应用和本次 qa/uat 环境内按完整 commit 查找唯一构建，不依赖额外部署平台接入；无匹配、同 commit 多构建、权限失败或时间预算耗尽均明确跳过。指定固定版本的既有入口保留，日常不要求员工填写；class ID 校验继续作为增强分析前的必要条件。
- 真实 FTP 验证复现 QA 的 190 个版本目录串行查询超过十秒；通配查询对实际存在的 commit 返回空，不能采用。按原目录布局使用最多八个独立只读连接分批查询，父目录读取和固定文件身份读取分别在并发批次前后，避免额外占用连接；仍查全后判断唯一性，沿用父进程硬截止时间，不增加缓存、重试或时间预算。该改动的实际消费者是自动材料定位，解决已复现的往返耗时，不以并发掩盖候选歧义。
- 真实迁移后的退款基准包含大段背景 JSON，原 `SELECT * ... ORDER BY` 实际触发 MySQL 1038。列表保留原可见性 SQL 和完整模型，仅在读取后按创建时间降序、同时间 ID 升序排序；不通过调大全局内存、增加索引或重试掩盖故障。
- 页面 500 复现为四连接读池等待两秒超时：完整接口列表逐项读取 69 次 SQL、约 26.6 MB 正文，一次服务日志耗时 288 秒；基准列表约 3.65 MB 也长时间占用连接。按已授权精确引用批量读取契约，Case 按唯一 Generation 批量读取并在本请求只解析一次；接口、Case 与基准沿用现有 MySQL COMPRESS 解码减少网络传输，保持完整响应和身份投影，不新增缓存、表或依赖。仅连接池租用超时转换为既有 metadata_unavailable/503，保留查询错误语义和原连接上限。

## 回归 Case 页面与受阻流程修复（2026-10-22）

- 沿用现有单 Case 与 published/mine 权限投影，页面按具体入口显示自己的 Case；不提供“全部入口”聚合项。目录与生成选择共用“接口→类→方法、MQ 消费、定时任务”的层级，只有存在真实入口的分类才显示。Case 库、生成任务、执行记录和覆盖增强各自独立，执行记录仅按需读取所选 Case 的结果与折叠请求响应。
- 已复现的跨基准目录缓存和同基准详情竞态，以现有范围检查和选择代次消除；生成弹框冻结目录来源视图，切换页面不能改变请求的知识视图。不新增持久状态或缓存设施。
- 目标与依赖只校验独立接口契约、固定源码及授权范围，不要求旧知识正文或内部逻辑长文。生成和操作使用用途及字段契约，Case 按需分析固定源码；真实缺口无法解决时保留草稿及具体原因，结束为失败或真实部分完成，独立知识访谈仍可问答。
- 登录身份失效统一撤销原生模态确认并关闭业务弹框；抽屉遮罩保持中性半透明。沿用现有页面版本检查并更新所有资产 URL，不以清浏览器缓存代替资产更新。

## 恢复独立接口契约边界（2026-10-22）

此前对“可靠知识”的判断错误复用了已废弃的完整知识正文门禁，与现行 `generation-knowledge-workflow` 和 `generalized-knowledge-workflow` 冲突。恢复接口用途及请求/响应契约作为共享保存、生成、依赖读取及执行兼容检查的依据；旧正文可保留，但不必生成、补齐或发布后才能生成 Case。本人完整契约草稿仍可直接生成和验证，向其他员工共享才需要显式发布。固定 commit、契约身份、运行时授权及真实断言验证不变；不修改线上历史复核行，已有 Case 可通过现有显式复核发布解除仅由旧正文造成的阻断。

## 失败任务复核（2026-10-23）

- 读取原任务及 Agent 工具回执，使用隔离存储重放草稿到部分发布的完整保存路径；不得把资格重算或模拟执行算成真实 QA 通过。用户目前不在公司，本轮不调用内网业务接口。
- 最新生成任务在员工、入口、基准和环境筛选后，按已有生命周期、进度及交接时间排序再分页。页面不把运行中的单步工具错误呈现为最终失败。
- 下游解析保留已有依赖缺口：零候选说明接口或材料缺失，多候选说明重载歧义，不让 Agent 在缺失 JAR 时反复修改签名。
- 原固定 POM 和本地 JAR 只读复现确认：日志接口不是本机缺包，而是离线 Maven 部分成功的 classpath 覆盖了已声明直接依赖。仅在该部分失败分支合并已有精确直接依赖，保留 Maven 顺序与调解版本；未解析的多版本声明保留缺口。此修复不下载包、不执行 Java 业务类、不改变完整解析或冻结依赖的路径。
- 原任务的发布拒绝已复现为读取投影差异，不是 Agent 草稿内容差异：MySQL 持久化清除 `SourceBaseline` 的机器目录，读取端按本机 `source-bindings` 回填；保存个人草稿却用回填后的 Generation 与原始载荷做严格模型相等比较。固定 Generation 的身份比较改用既有可移植载荷，源码目录仍由本机读取投影，实际内容、绑定或依赖变化继续拒绝。P13 的隔离内存重放没有覆盖该读取投影，不能作为跨机器保存已通过的证据；本轮以原任务 revision 3 提交在回滚事务中重放真实读取、保存和发布路径。
