## ADDED Requirements

### Requirement: 覆盖增强按员工与环境重试
系统 SHALL 允许发起员工对失败或跳过的增强显式重试，并允许对已完成轮次从增强后的Case集显式开始新轮次；失败/跳过创建关联原根任务的新 attempt，已完成轮次建立新根，同一接口同一时间最多一个活动 attempt。复用已成功且输入仍匹配的阶段，必要时明确重新执行 Case。详情、报告和再次执行 SHALL 仅向发起员工开放，并且仅限其当前可见内容。

#### Scenario: 发起新增强或重试
- **WHEN** 员工开启覆盖增强生成或点击重新执行覆盖增强
- **THEN** 先确认测试环境部署版本为当前固定基准 commit 和环境，确认后才创建任务；取消无副作用

#### Scenario: 手动创建新的增强根任务
- **WHEN** 员工未提供 retry_of 并请求对当前接口的Case集发起首轮增强
- **THEN** 与自动入口一样核验系统启用策略、候选自身和前驱链资格，自动登记不能递归创建新的模型轮次
- **AND** 已完成轮次的显式再次执行从增强后的Case集开始新根轮次，不修改原轮次证据，也不由自动登记再次触发

#### Scenario: 补充模型未发布时重试
- **WHEN** 上轮增强为 `PARTIAL`、复测仍为 `PENDING`，且没有 READY 的增强 Generation 或记录为 `SUPPLEMENT_NOT_PUBLISHED`
- **THEN** 允许作为补充失败重试，复用有效基线和缺口，重新派发补充任务
- **AND** 不得把复测标成成功，也不得把普通 `PARTIAL/PENDING` 且已有 READY 增强产物的任务误放行

#### Scenario: 已有增强继续成功阶段之后的工作
- **WHEN** 员工通过 retry_of 恢复已授权 attempt
- **THEN** 继续遵守原任务范围及阶段复用，不将恢复当作新根请求，也不因此重复模型或已完成业务

#### Scenario: 换电脑重试
- **WHEN** 同一员工在另一电脑打开仍可见的 Case
- **THEN** 可从 S3 获取原固定源码、字节码及 exec 材料，校验有效后复用分析；未知业务结果先核查而不盲目重放

#### Scenario: 其他员工查看覆盖详情
- **WHEN** 非发起员工请求增强详情、报告或重试
- **THEN** 拒绝该请求；其仍可对当前共享 Case 发起属于自己的增强

#### Scenario: 同接口多Case属于同一轮次
- **WHEN** 同一 Generation 的多条 Case 属于同一轮测量
- **THEN** 接口覆盖页展示完整测量集合和汇总计数，不按当前点击的 Case 拆分；单条 Case 的旧详情查询仍只能展示其实际参与的测量，不能把汇总结果冒充该 Case 独占

#### Scenario: 补充任务创建后遇到排他任务
- **WHEN** 已保存补充子任务，但模型派发在持久化运行回执前被明确的排他门禁拒绝
- **THEN** 创建任务的 start 或 continue 回执不算模型已运行；门禁解除后仅派发同一子任务和稳定请求
- **AND** 已有模型运行、原生会话或草稿写回证据时只观察，不重复派发

#### Scenario: 中文状态与真实测量
- **WHEN** 页面展示增强状态
- **THEN** 展示中文原因、最多三十项确定性代码缺口与处置、两次测量的真实计数；缺失计数保持未知，超出范围或无法判定的内容提示需复核

### Requirement: 覆盖增强按接口展示最近一轮
系统 SHALL 按当前接口展示发起员工最近一次覆盖增强，包含增强前后行覆盖率、本轮新增并验证的Case、最后一次有效测量的未覆盖代码和源码入口；页面不得要求先选择单条 Case，也不得把缺失计数展示为零。再次执行 SHALL 对当前接口生效，不依赖某一条 Case 的独立状态。

#### Scenario: 打开接口覆盖页
- **WHEN** 员工打开当前接口的覆盖增强栏目
- **THEN** 读取该员工、当前代码基准和环境下的最近一轮，展示增强前后行覆盖率、最近时间和真实状态；不按Case比例拆分，也不读取其他员工或环境
- **AND** 行覆盖率按接口已解析调用范围统计，范围不完整时展示真实说明，不宣称全应用覆盖率

#### Scenario: 尚无有效计数
- **WHEN** 基线或复测没有有效dump/分析
- **THEN** 对应数值显示未知并保留原因，不按零计算；复测无效时保留有效基线，不伪造增强后百分比

#### Scenario: 本轮新增Case
- **WHEN** 增强生成包含基础Generation之外的Case
- **THEN** 按服务端冻结的精确来源和编译时可执行内容比较，分别展示基础复测、调整与新增项及逐项验证结果；历史缺少来源时显示未知，不以新分配的 Case ID 差集冒充新增；验证通过、未通过和待验证分开呈现

#### Scenario: 未覆盖代码与源码
- **WHEN** 最近一次有效分析存在代码缺口
- **THEN** 按文件、方法和连续行区间归并展示，整方法缺口不伪造精确末行；源码只在用户点击时从本次固定材料按需读取，并只允许读取该次缺口路径
- **AND** 源码正文、完整路径定位和原始exec不进入列表投影；材料缺失或路径不匹配时明确提示，不读取本机工作树或其他版本源码

#### Scenario: 已完成轮次再次执行
- **WHEN** 员工对已完成轮次点击再次执行增强
- **THEN** 先确认部署版本，再以增强后的Case集作为新基线准备执行，建立独立新根和新任务；原轮次工作流、报告和Case绑定保持不变
- **AND** 自动登记仍不得递归；同接口已有活动轮次时拒绝并发执行，失败或跳过后仍从原根重试而非新建轮次

#### Scenario: 首轮由接口入口发起
- **WHEN** 当前接口没有历史增强，员工从接口覆盖页发起执行
- **THEN** 使用该Generation的完整可见Case集，不缩小为被点击的一条；Case不可见时明确阻止，不以其他视图的内容补齐

### Requirement: 覆盖增强的选择与范围展示必须可核实

系统 SHALL 区分“已解析调用范围”和“完整业务路径”，并只从当前接口的固定扫描证据展示范围限制。首轮增强的 Case 选集 SHALL 使用员工确认视图中的固定 Generation/Variant；任一绑定不可见、不可执行或版本变化时 SHALL 在创建执行、reset 或业务调用前明确阻止。已完成轮次的新轮次 SHALL 使用增强后 Generation 的冻结 Case 绑定，逐项核对精确版本与可见性；不得用锚点 Case 的单一视图过滤掉仍然合法的增强 Case，缺项必须明确阻止，不得静默缩小。

#### Scenario: 首轮增强按确认视图选择
- **WHEN** 员工从接口覆盖页发起首轮增强并确认部署
- **THEN** 只选择请求视图内与固定 Generation/Variant 完全一致且可执行的 Case
- **AND** 任一固定绑定在该视图不可见、不可执行或版本已变化时，在创建执行、reset 或业务调用前明确阻止，不从其他视图补齐
- **AND** 不得缩成只执行被点击的一条 Case

#### Scenario: 已完成轮次使用冻结增强集合
- **WHEN** 员工对已完成轮次再次执行增强
- **THEN** 使用增强后 Generation 的固定 Case 绑定逐项核对精确版本和当前可见性
- **AND** 不按锚点 Case 的单一视图过滤增强集合；任何绑定不可见或不可执行时明确阻止
- **AND** 原失败/跳过重试仍保持原冻结集合，不按当前页面重新选取

#### Scenario: 范围限制与覆盖率计数
- **WHEN** 页面展示有效覆盖测量
- **THEN** 同时展示 covered/total 行和实际进入范围的方法数
- **AND** scope_status=PARTIAL 时使用通用说明“仅统计已解析调用范围，不代表完整业务路径”
- **AND** 只单独展示当前接口已确认的未解析调用点（调用方、表达式、原因、位置）；没有确认断点时不得推断业务路径未覆盖，也不得把所有 PARTIAL 归因为同一原因
- **AND** 没有有效分析时显示未知，不补 0 或 0/0

### Requirement: 覆盖状态读取与辅助复核不阻塞任务
系统 SHALL 使用轻量状态投影报告真实阶段、开始结束时间及最近活动；复测读取失败和因当前版本变化不可查看 SHALL 明确区别于从未增强。保存缺口处置 SHALL 非阻塞派发本轮唯一辅助复核，复用既有 worker 与 model_runs；复核等待上限 SHALL 可配置且默认180秒，从登记开始计算，维护不得同步等待模型。

#### Scenario: 慢复核或服务重启
- **WHEN** 辅助复核尚未结束、启动失败或服务重启
- **THEN** 保存请求及时返回，已有运行只观察不重复付费派发；超过持久化截止时间标为不可用并停止该辅助进程
- **AND** 辅助建议不构成发布审批门槛，过期或已进入验证的返回不得改写已采用处置

#### Scenario: 新草稿不沿用旧复核结论
- **WHEN** 草稿保存为新的修订，或读取仍残留旧复核内容的历史草稿
- **THEN** 新修订不携带旧修订的逐缺口复核结论，晚到复核也不得写入；过期或已失效的辅助复核仍可按不可用由生成模型最终判断
- **AND** 首次最终提交不能仅利用本次修订号递增绕过原本仍在进行的有效等待，不创建第二次辅助复核

#### Scenario: 基础复测与增强复测
- **WHEN** 对接口发起增强
- **THEN** 执行完整固定集合的基线，再补充并验证完整增强集合；页面显示各阶段，不将整集耗时说成单条 Case 耗时，也不额外重复验证

## MODIFIED Requirements

### Requirement: 覆盖增强必须核对实际构建制品及 reset 条件
系统 SHALL 在员工确认部署版本后，按任务固定的当前代码基准 commit 和 QA/UAT 环境自动取得实际构建 WAR/JAR、完整业务类及对应源码，并核对 dump 中可比较类 class ID。材料来源预先接入，日常生成不得要求员工逐次维护部署包路径、artifact_commit 或 archive_version；FTP 不是必需的下载协议。部署确认不代替制品核对，reset 必须具有所选环境的明确许可。

#### Scenario: 确认后自动取得材料
- **WHEN** 员工确认当前环境部署与固定基准一致，且部署材料来源已接入
- **THEN** 自动读取基准固定源码并定位匹配的实际构建产物，再进入覆盖采集，不要求员工另行提供 IP、包路径或下载密码
- **AND** 未确认不启动增强；无法取得匹配产物时明确保留缺失原因，不使用旧包、本机重新编译结果或其他环境产物代替

#### Scenario: 运行材料不匹配
- **WHEN** 固定 commit 的实际制品缺失、源码不对应或 class ID 不匹配
- **THEN** 跳过增强并保留基础 Case 与验证，不使用其他环境或最新包代替

#### Scenario: reset 许可未配置
- **WHEN** 所选环境没有明确允许清零
- **THEN** 保持默认禁止 reset，记录跳过原因，不采用累计差分冒充独立测量

#### Scenario: 固定本地或归档制品
- **WHEN** 使用本地或 FTP 材料
- **THEN** 本地需完整 commit 和真实文件；FTP 使用所选环境的明确归档环境段、解析出的版本目录及凭据引用，具体来源由接入配置与部署材料定位结果提供
- **AND** 执行前固定原生文件身份，dump 后复查身份与字节码，不根据环境名猜测 UAT 归档路径

#### Scenario: FTP 自动定位唯一构建
- **WHEN** 已配置 FTP 来源及凭据引用，但未逐次指定 archive_version
- **THEN** 程序只读取当前应用下本次选定的 qa 或 uat 目录，按固定完整 commit 查找构建目录，并核对其中唯一 WAR 及对应 out.tar.gz
- **AND** 不跨环境读取，不把不安全的目录名称拼入路径，不用文件时间或分支名替代 commit 匹配；文件时间只在 commit 已匹配的构建之间选择最新

#### Scenario: 同commit多构建按WAR构建时间选择最新
- **WHEN** 同一 commit 出现在多个版本目录，且每个候选都有唯一 WAR 和可读取的 MDTM
- **THEN** 选择唯一 WAR 的 MDTM 最新的构建，并记录所用构建时间；不按目录顺序、版本名或构建号代替时间
- **AND** 最新构建时间并列时仍按歧义跳过，不能任选其一；选中WAR/源码的文件身份及dump后的class ID核对仍必须通过

#### Scenario: 归档候选无法确定
- **WHEN** 同 commit 有多个构建且最新时间并列、材料不完整、目录无法读取或查找超过准备时间预算
- **THEN** 明确记录原因并跳过增强，不把并列候选中的任一个当成已部署构建，不把权限或超时错误解释为其他候选不存在

#### Scenario: 当前环境存在大量历史版本
- **WHEN** 自动定位需要检查当前应用及所选 QA/UAT 的多个版本目录
- **THEN** 使用最多八个独立 FTP 连接分批只读查询，各连接独占当前目录状态，所有批次成功后才判断唯一性
- **AND** 不依赖服务器通配查询，不增加本轮 180 秒共享准备预算；该预算为临时放宽，待真实耗时稳定后再按阶段收敛；超时仍由现有父进程终止并回收整个只读采集进程，不能留下连接继续采集或迟到 reset

### Requirement: 覆盖辅助生成必须固定所选源码版本
系统 SHALL 只使用用户当前查看的代码基准生成，不再接受独立 source_revision 选择，不追踪 QA 最新分支；任务冻结 commit、scan、知识及环境。

#### Scenario: 生成当前基准 Case
- **WHEN** 员工在当前基准点击生成
- **THEN** 使用该基准当前可见知识及精确扫描，缺失时先补齐，不静默改用系统 pin/latest

#### Scenario: 任务期间切换基准或环境
- **WHEN** 页面切换选择或来源 tag 移动
- **THEN** 原任务及其 continue、补充、重试继承冻结的 commit 与环境

### Requirement: 覆盖增强应为有明确边界的可选能力
系统 SHALL 对启用增强、READY、generate_and_verify、所选 QA/UAT 的基础版本尝试测量；增强与业务结果分开，采集不可用不得阻断基础 Case。

#### Scenario: 不符合测量条件
- **WHEN** 增强关闭、配置缺失或基础版本 PARTIAL
- **THEN** 记录原因并保留原验证；generate_only 不执行业务或 reset

#### Scenario: 单实例适用条件
- **WHEN** 用户确认启用覆盖增强
- **THEN** 提示所选环境整轮需只有一个承接请求的 JVM 及多实例误报风险，不假称已自动证明副本数量

#### Scenario: 无法归因的实例快照
- **WHEN** 展示测量计数或缺口复测
- **THEN** attribution 保持 UNVERIFIED、因果结论保持 INCONCLUSIVE、verified_resolved_count 为 null，不宣称接口独占覆盖率

### Requirement: 实例发现与配置应与生成流程解耦
系统 SHALL 复用可替换的 InstanceDiscovery 和既有有界天网日志查询，系统级 appId/token 不随 QA/UAT 重复保存；环境配置指定日志网关、日志环境覆盖及明确归档环境段。

#### Scenario: 查询 QA 或 UAT 日志
- **WHEN** 所选环境、系统身份及网关可用
- **THEN** 使用该环境查询最近十分钟窗口、每页五百最多五页，核对 appId、env、IP、appUk 与时效；分页不完整或预算耗尽时跳过
- **AND** UAT 缺少网关或归档配置时明确缺失，不回退 QA

#### Scenario: 容器日志自动定位采集实例
- **WHEN** 天网日志的 ip 字段为容器名称且 serverIp 提供实例数字地址
- **THEN** 使用校验通过的 serverIp 和当前环境配置的 JaCoCo 端口自动定位，不要求员工补填实例地址
- **AND** 仅在 serverIp 缺失或为空时兼容旧日志的数字 ip；显式非空但非法的 serverIp 必须拒绝，不能改取其他字段掩盖错误

#### Scenario: 保存凭据与设置
- **WHEN** 更新系统天网设置
- **THEN** 凭据只在本机权限受限配置中保存，普通响应只返回已配置状态，省略保留、显式清空才删除；不进入共享记录或模型

### Requirement: 自动执行必须在提交后按精确绑定派发
系统 SHALL 在短事务登记自动执行、实际任务进程 owner 及增强引用，提交后才向既有线程池派发；每个 attempt 中每段绑定的执行至多派发一次。

#### Scenario: 执行接入采集
- **WHEN** 自动执行开始
- **THEN** 仅精确 execution_id、系统、Generation、冻结环境和阶段均匹配才采集；其他执行不触发 reset

#### Scenario: 发布请求重试
- **WHEN** 已有自动执行绑定
- **THEN** 返回原绑定而不读取最近执行或重复派发，关联缺失或不匹配明确报错

#### Scenario: 合法空执行绑定
- **WHEN** 登记时跳过或增强版本 PARTIAL
- **THEN** 保留原验证路径，不伪造覆盖执行引用

### Requirement: 测量窗口应复用原验证并保持非阻断
系统 SHALL 非阻塞取得 system_id 加 environment 的测量锁，在临时 180 秒准备预算内完成发现、制品固定和 reset，再在原验证后 dump；下载及分析在释放测量锁后完成。

#### Scenario: 同系统同环境锁忙
- **WHEN** 另一员工正在同系统同环境测量
- **THEN** 立即跳过采集且保留业务验证，不排队 reset；同系统不同环境互不占用此锁

#### Scenario: dump 后分析
- **WHEN** 已完成业务及断言并保存 dump
- **THEN** 使用执行前固定材料分析，不取最新包；采集失败不修改业务结果或重放业务

#### Scenario: 两个独立测量阶段
- **WHEN** 增强产生可执行补充版本
- **THEN** baseline 和 verification 分别独立 reset、执行、dump 并保存真实计数，不叠加为因果提升

### Requirement: 增强结果应持久化并按配置保留诊断材料
系统 SHALL 复用现有 MySQL 工作流和执行聚合保存状态、至多三十个缺口处置、模型引用和 S3 对象引用；实际 exec、源码、字节码及可重建报告材料保存 S3，默认永久保留，不再按系统或接口仅保留最近一份。

#### Scenario: 保存两段报告
- **WHEN** baseline 或 verification 材料取得成功
- **THEN** 保存实际材料和明确的阶段引用；未知或失败的写入不声称成功，已完成分析保留真实计数

#### Scenario: 跨机器读取本人材料
- **WHEN** 发起员工在另一电脑请求报告
- **THEN** 后端校验员工和当前内容可见性，再读取固定 S3 材料；不依赖原工作台的私有路径，不向模型暴露存储凭据

#### Scenario: 新报告完成
- **WHEN** 后续报告完成或旧窗口迟完成
- **THEN** 保留旧材料和现有业务执行，不执行旧的最近一份裁剪规则

### Requirement: 有效证据与终态收尾必须可重入
系统 SHALL 在有效 dump 或分析持久化后保留证据，使用既有任务池及严格 owner 恢复；分析与收尾失败不作废材料，不重新执行已完成业务。

#### Scenario: 分析派发失败或终态收尾失败
- **WHEN** 材料已保存但派发失败，或分析已保存但收尾失败
- **THEN** 从未完成阶段恢复，不重新采集或重放业务

#### Scenario: 多进程接管
- **WHEN** 两个服务尝试接管已退出 owner
- **THEN** 系统事务内重读 owner、执行与 revision 并原子确认唯一接管者；健康 owner 只观察，通用孤儿恢复不覆盖专用接管

#### Scenario: 终态重复收尾
- **WHEN** 已完成工作流再次收尾
- **THEN** 保持终态及结束时间，不重写大材料；旧的待裁剪内部标记仅清理为已退休规则，不触发删除

## REMOVED Requirements

### Requirement: 终态维护不得重复制造已完成的裁剪待办
**Reason**: 本期材料默认永久保留，退休最近一份裁剪及其待办。
**Migration**: 读取旧记录保留材料并清理旧 INTERNAL 裁剪标记，不重新派发裁剪任务。
