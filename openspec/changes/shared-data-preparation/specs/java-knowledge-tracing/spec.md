## ADDED Requirements

### Requirement: 按需源码分析保留可核查业务证据

系统 SHALL 为接口契约补充、数据准备和Case生成按需读取固定版本的实现、校验、业务方法及外部依赖，并保留结论所需的源码路径、符号、行号与扫描版本；不得以先发布入口内部知识长文作为前置。

#### Scenario: 分析补单所需数据关系
- **WHEN** 补单任务需要确定报表ID和出票原单如何关联
- **THEN** Agent可从授权的固定源码追踪对应查询、绑定和状态校验，将方法与验证规则提交到本任务
- **AND** 不要求同时维护所有内部方法的自然语言说明

#### Scenario: 无法确认运行约束
- **WHEN** 动态调用或未确认生效的注解不足以证明实际约束
- **THEN** 契约保留未知及已有证据，只就当前任务必需的缺口继续分析或提问

## REMOVED Requirements

### Requirement: 入口知识可追溯到深层业务规则
**Reason**: 内部知识长文不再作为独立批量维护目标。
**Migration**: 源码追踪保留为契约、数据和Case任务按需使用的工具。

### Requirement: Java知识生成必须输出typed入口事实候选
**Reason**: 新流程不再要求先发布入口Fact候选。
**Migration**: 结构化输入约束归接口契约；数据身份、关系和状态归共享方法及运行验证；历史候选保持可读。
