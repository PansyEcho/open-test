# Design

## 数据职责

接口契约复用 Operation 的结构与扫描证据并独立持久化按需补充结论。未知约束仅阻塞实际依赖它的步骤。共享数据定义保存输入、有限步骤、输出绑定、前后条件及来源版本；JSON 发布版本不可覆盖。执行记录另存私有目录，保留真实条件、操作证据、实际环境和验证结果。

## 执行

优先查询；无匹配时仅执行本次已授权且定义中存在的创建步骤。状态不符时只调整明确允许的状态。主体或关联不符不得静默替换条件。创建或调整后回查验证，未达标不调用目标接口。复用现有幂等 Operation 和有限谓词，补充 JSON 解码及运行期断言，不增加通用表达式或重试。

## 兼容与基线

Generation 已有 input_contract、submission.data_functions、case_templates 和 variants；选择共享版本后内嵌完整定义，仅增加来源版本说明。运行时按 handoff 固定 scan 解析 Operation，项目接入状态与所选逻辑环境仍在运行时校验。历史定义及报告不重写，历史 cleanup 不再在新执行中运行。

## 现行要求迁移

现行规范中的批量内部知识、强制 program-case 目录和正式 Fact 前置要求在本变更中明确移除或改写；历史知识、Fact、清理声明及报告继续保留。结构化字段、约束和源码证据迁移到独立契约，Case 场景与预期仍由 Case 生成阶段负责，不新增回归点资产。Case 工具开放当前任务所需的受控源码读取与固定版本共享方法读取，生成阶段仍禁止执行业务操作。系统 Skill 的缺输入流程先复用数据方法，再对必要缺口提问；Skill 被调用本身不代表执行授权。

## 任务与界面

继续使用 TaskRecord 和现有 handoff、问答、运行及会话诊断；契约补充属于原业务任务阶段。新增共享能力目录及独立执行入口，知识页不承载全局任务。Agent 结束只有在资产已发布或运行结果已验证时才代表业务成功。

## 验收

以补单系统 ReportFacade 查询/保存报表，关联出票原单，调用退票 RefundFacade#billSupplement 为有限流程。请求 id 必须来自分销报表；使用测试系统现有数据，允许已声明的状态调整。分别验证两个 Case、自然语言任务复用，同一 G1 不受能力更新影响，以及四类失败分类。

## 两层关系与项目环境

复用扫描DSF引用和发布坐标、MQ实际集群/Topic/消费条件，按需汇总有向关系及证据；不增加人工关系存储。每个方向独立BFS，起点已访问，最多深度2，到达第2层不展开；去重排除自身且不改变遍历方向。只读API返回上下游深度、关系证据与识别缺口，旧修改接口退役，历史绑定不再作为新发现或执行门槛。

已接入且位于两层范围的项目操作默认可用于新任务，无逐关系操作/用途配置。生成不执行，查询和观察只读，明确造数任务可写后回查。固定Generation沿用原定义与源码范围；执行只检查目标项目仍接入及Profile有效。项目qa/uat配置各自选实际filter qa/test/dev/uat，连接、DSF身份与资源值只在本次运行开始解析并在内存复用。旧test selector不猜测为qa；历史记录和test.yaml保留，新目录仅qa/uat。旧External DSF不可绕过目标项目接入，不能静默切换调用身份。
