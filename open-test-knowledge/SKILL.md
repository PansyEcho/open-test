# OpenTest Knowledge

本目录是业务知识的Git真相源。SQLite只负责本地检索加速；结论、关系、Case和人工确认都以这里的Markdown/YAML为准。

## 路由流程

1. 读取 `registry/systems.yaml`，按 `system_id` 和业务描述定位系统。
2. 读取 `systems/<system_id>/SKILL.md`，遵循该系统的检索顺序和证据约束。
3. 优先通过精确知识ID、代码符号和别名定位；结果过多时再使用全文检索。
4. 需要解释深层逻辑时，沿 `relations.yaml` 的调用、依赖、读写和状态关系扩展一跳，再按需继续。
5. 回答时区分代码确认、推断、用户确认、环境观察、冲突和过期状态，并引用节点中的源码证据。

## 使用边界

- 一期只有一个DSF系统，不创建跨系统关系或跨系统Case。
- 不从 `.opentest/index.sqlite` 反向覆盖知识文件；索引损坏时删除并从知识文件重建。
- 自动生成区域位于 `<!-- kb:auto-start -->` 与 `<!-- kb:auto-end -->` 之间；更新时不得覆盖其外的人工内容。
- 自然语言场景必须先编译为结构化约束。知识不足时列出缺失条件，不猜测业务事实。
- 稳定业务结果可作为硬断言；易变内部参数只保留为诊断证据。

## 常见任务

- 业务解释：读取入口节点，沿关系展开业务规则、数据访问、下游和状态流转。
- 场景构造：读取 `cases/` 和覆盖目标，将自然语言条件转换为可重放变体。
- 需求评审：查找受影响入口、公共逻辑和状态关系，明确已覆盖与缺失决策。
- 回归分析：结合节点源码证据、源码基线和Snapshot判断知识与Case是否过期。

不要一次加载所有系统或所有reference；按问题逐步读取，保持证据上下文可核查。
