# OpenTest 开发质量门禁

## 编码

- 每个新增或修改函数必须有中文文档注释，说明业务目的、参数、返回值和重要副作用。
- 非平凡函数在重要阶段、业务分支、并发、重试、缓存和错误恢复前添加解释原因的注释。
- 新签名默认不超过五个显式参数；参数对象必须具有独立业务含义。
- 不用弱类型容器掩盖长参数列表，不为降参数数量创建一次性包装类型。

## 日志

- 工作流入口绑定 `trace_id`、`filter1=system_id` 和 `filter2=task_id/run_id`。
- 仅记录关键阶段、状态变化、业务标识、耗时和失败边界。
- 在 `finally` 中清理日志上下文，防止线程复用泄漏。

## 验证

- OpenSpec工件在编码前和归档前执行严格校验。
- 每个任务完成时同步更新 `tasks.md` 与 `docs/status.md`。
- 运行V2相关测试、legacy完整测试和确定性纵向集成测试。
- 源码或可执行配置变化完成后，使用OCR delegation模式审查任务完整差异。
- 合理的High/Medium问题修复后重跑受影响验证。
